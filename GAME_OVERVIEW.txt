1) PRODUCT SUMMARY
- Genre: endless arcade action
- Platform target: mobile-first web game in portrait orientation
- Tech: plain HTML, CSS, and vanilla JavaScript
- Renderer: single 2D canvas for gameplay
- Session flow: main menu -> run -> game over -> restart/menu/shop
- Core fantasy: a player ball clings to the arena walls and slices through moving target balls before a short timer expires

3) SCREEN AND UI MODEL
- The game is designed for phones first.
- The visible playfield is a square `420 x 420` arena inside a taller portrait layout.
- HUD outside the canvas:
  - score
  - combo
  - timer bar and timer text
  - short tip copy

4) CORE GAME LOOP
1. Start a run with one full-size target ball in the arena center.
2. The target is already moving before the first dash.
3. The player starts attached to the bottom wall.
4. A tutorial line shows an opening path from the player through the first target.
5. The timer does not start until the first real launch.
6. Player swipes to dash from the current wall point to another wall point.
7. During a dash, resolve all pre-existing target hits in path order until a spike or temporary wall interrupts the dash.
8. Every successful hit:
   - `+1` score
   - `+1` coin
   - combo increment
   - timer reset to `3.0`
9. Non-minimum targets split into two smaller moving children.
10. Minimum-size targets explode and are removed.
11. When the last live target is gone, spawn one new full-size target and continue the endless wave loop.
12. Game over occurs immediately when the timer reaches `0`.


5) CONSTANTS THAT DEFINE FEEL
- Arena size: `420 x 420`
- Player radius: `14`
- Timer duration: `3.0` seconds
- Dash speed: `4800`
- Dash duration clamp: `0.08` to `0.14`
- Dash cooldown: `0.15`
- Target start radius: `60`
- Target minimum radius: `32`
- Target shrink per split: `14`
- Target movement speed:
  - base `62`
  - grows by `0.55` per successful hit
  - capped at `104`
- Spike unlocks:
  - first at `10` hits
  - second at `25` hits
  - third at `60` hits
  - fourth at `100` hits
- Temporary wall unlock:
  - `85` hits
- Temporary wall timings:
  - warning `0.78`
  - active `2.0`
  - next delay random `1.9` to `3.8`


6) PLAYER MODEL
- The player is a wall-bound ball while idle.
- The player does not free-roam inside the arena.
- Every move is a dash from one wall position to another wall position.
- After each dash, the player reattaches to the destination wall.
- Input:
  - pointer down anywhere in the arena starts aim mode
  - aim guide shows projected line and landing point
  - release launches
- Repositioning is intentional:
  - moving to a better wall spot before attacking is part of play


7) TARGET SYSTEM
- Live targets are stored as an array, not as one special center object.
- Every target stores:
  - `id`
  - `x`, `y`
  - `prevX`, `prevY`
  - `vx`, `vy`
  - `radius`
  - `stage`
  - `pulse`
  - `flash`
  - `bornShotId`

Wave lifecycle:
- Wave start:
  - one full-size target
  - centered in arena
  - random drift direction
  - current size ladder is `60 -> 46 -> 32 -> explode on next hit`
- Successful hit on a non-minimum target:
  - remove the hit target
  - create two child targets
  - child radius = `max(CORE_MIN_RADIUS, parent.radius - CORE_SHRINK_PER_HIT)`
  - place children on opposite sides of the slice normal
  - inherit parent drift direction with mirrored split impulse
  - children are rendered immediately
- Successful hit on a minimum-size target:
  - remove the target
  - play a richer explosion
  - do not create children
- When `targets.length === 0`:
  - spawn one new full-size target
  - trigger a larger respawn burst

Shot gating:
- Targets created during the current shot are tagged with `bornShotId = currentShotId`.
- Those children are not eligible to be hit by the same dash that created them.
- They become hittable on later dashes.


8) TARGET MOVEMENT AND PHYSICS
- All live targets drift continuously while a run is active, even before the timer starts.
- Movement does not pause while split shell effects are active.
- Target balls bounce off arena bounds.
- Target balls bounce off each other using disc collision response.
- Targets and spikes also bounce off each other using the same disc collision response.
- Mass should be proportional to `radius^2`.
- Collision resolution must:
  - separate overlap
  - update velocities using elastic-style response
  - clamp discs back inside arena bounds


9) PLAYER-HIT COLLISION RULES
- Player collision uses swept circle checks because both the player and targets move quickly.
- For every dash frame:
  - collect target hit events for all eligible live targets
  - collect the earliest spike hit
  - collect the temporary wall hit if one exists
- Sort by impact time `t`.
- On ties, target hits win over hazards.
- Process sorted events in order:
  - target hit -> split or explode target and continue
  - spike hit -> bounce player back toward launch wall and stop the chain
  - temporary wall hit -> same interruption behavior as a miss and stop the chain
- A dash can cut multiple pre-existing targets in one pass.


10) TARGET FX MODEL
- Transient target effects are stored separately from live targets.
- Two effect families are required:
  - `split`
    - stores center position, impact point, cut direction, original radius, elapsed time, duration
    - draws the old shell cut in half and peeling apart
  - `burst`
    - stores center, base radius, colors, elapsed time, duration
    - draws expanding glow and ring effects

Split visual:
- Draw live targets first.
- Draw split shell halves on top.
- The new children are visible underneath the old shell effect.
- The shell halves shrink and fade as they separate along the slice normal.

Explosion visual:
- Small-target death must feel more alive than before:
  - more sparkles
  - ember dots
  - shard pieces
  - ring pulse
  - glow flash
- Board-clear respawn burst is larger than a regular small-target explosion.


11) SPIKES
- Spikes are moving circular hazards rendered with spike teeth.
- Count:
  - 0 before `10` successful hits
  - 1 at `10`
  - 2 at `25`
  - 3 at `60`
  - 4 at `100`
- Speed:
  - base `76`
  - scales with difficulty
  - capped at `190`
- Spikes bounce off walls, other spikes, and live target balls.
- Spikes are no longer forced away from the target area.
- If the player dash hits a spike before finishing its target chain:
  - player rebounds toward launch wall
  - dash is treated as a miss


12) TEMPORARY WALL HAZARD
- Unlocks at `85` successful hits.
- Telegraph with a warning lane first.
- Spawn as a glowing horizontal or vertical line segment.
- This hazard affects only the player, not target balls.
- If the player intersects it during a dash:
  - the dash is interrupted
  - the player rebounds
  - the attempt is a miss


13) SCORE, TIMER, COMBO, COINS
Timer:
- Starts only on first real dash
- Resets to `3.0` on every successful split or explosion hit
- Time out ends the run immediately
- Low time heats up the map visually

Score:
- `+1` per successful target hit

Combo:
- increments on successful hit
- resets on miss
- best combo tracked for run summary

Coins:
- `+1` per successful target hit
- persisted between sessions


14) ONBOARDING
Opening slice guide:
- Visible only at the beginning of a run
- Drawn from the player toward a valid wall destination through the lead target
- Hidden on first real launch or after the guide timer fades

One-time reposition hint:
- Shown only once for a new player
- Explains the player can move to another wall position before attacking
- Persisted in profile storage
