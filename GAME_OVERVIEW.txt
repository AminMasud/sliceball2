SLICEBALL 2
GAME OVERVIEW (CURRENT BUILD)

1) PROJECT SUMMARY
- Platform: Web, mobile-first portrait layout
- Stack: HTML + CSS + JavaScript
- Renderer: Canvas 2D
- Runtime entry: `game.js` loaded by `index.html`
- Mode: Endless single-player arcade


2) CORE GAME LOOP
1. Attacker starts attached to a wall.
2. Opening tutorial guide shows a valid path from the attacker to the center core.
3. Survival timer does not start until the player's first real dash.
4. Player swipes to choose a wall-to-wall dash path.
5. If the dash reaches the center core before another collision resolves first, it counts as a successful hit.
6. Score, combo, coins, timer, and core radius update.
7. Hazards continue moving and the target keeps shrinking.
8. Run ends when timer reaches 0.


3) CENTER CORE TARGET
- The main objective is a large orb fixed at the middle of the arena.
- Core behavior:
  - starts large
  - shrinks after every successful hit
  - stops shrinking at a minimum radius
- Successful core hit reward:
  - `+1` score
  - `+1` coin
  - combo increment
  - timer reset to `3.0` seconds


4) MOVEMENT MODEL
- Attacker:
  - wall-attached while idle
  - no free movement inside the arena
  - very fast dash travel
  - dash duration is short (`~0.08` to `0.14 sec`)
  - post-dash attach pulse on wall impact
- Dash cooldown:
  - `0.15 sec` safety cooldown between dashes
- Dash target:
  - always resolves to a wall landing point based on swipe direction


5) INPUT / AIM / TUTORIAL
- Touch or swipe can begin from anywhere in the arena.
- Aim preview shows:
  - full projected dash path
  - wall landing marker
- Opening tutorial guide:
  - starts from the attacker
  - points through the center core toward a valid wall target
  - stays visible until the first actual launch


6) COLLISION / PHYSICS MODEL
- Core hits use swept circle collision.
- Spike hits use swept moving-circle collision.
- Collision order:
  - earliest impact during the dash step wins
  - tie-break currently favors the core target over hazards
- Spike reflection:
  - still rebounds the attacker back toward the launch wall
- Arrow hit:
  - counts as a miss


7) DIFFICULTY
- Difficulty now comes from:
  - the shrinking center core
  - moving spikes
  - late-run arrow hazards


8) TIMER / COMBO / COINS
- No heart system.
- Survival rule:
  - player must land at least `1` core hit every `3.0` seconds
  - timer starts only after the first dash
  - timer reaching `0` immediately triggers game over
- Low-time feedback:
  - map visually heats up when close to timeout
- Miss:
  - no point is awarded
  - combo resets to `0`
  - `MISS` banner + red flash
- Coins:
  - `1` coin per successful core hit
  - persisted in `localStorage`
- Record:
  - best score is saved in `localStorage`
  - shown in menu and game-over screen


9) HAZARDS
- Spikes:
  - 1st spike unlocks at `5` hits
  - 2nd spike unlocks at `30` hits
  - spikes move across the arena
  - spike collision rebounds the attacker and invalidates the dash
- Arrows:
  - unlock at `50` hits
  - warning lane appears before spawn
  - arrow hit counts as a miss


10) ATTACKER SKINS (COSMETIC)
- Character silhouette:
  - round attacker ball
  - thick outline + glow aura
- Skin roster:
  - Neon Ninja: default unlocked
  - Fire Ninja: `150` coins
  - Water Ninja: `150` coins
  - Lightning Ninja: `250` coins
  - Earth Ninja: `250` coins
  - Blossom Ninja: `300` coins
- Skin effects are cosmetic only.


11) VISUAL FEEDBACK
- Dash:
  - themed trail segments
  - themed particles
  - meteor-style movement flare
  - afterimages
- Core hit:
  - spark burst
  - core pulse / flash
  - warped pop-up banner
  - screen flash + optional shake
- Arena:
  - bright near-white playable map interior
  - warm framed outer shell
  - low-time heat shimmer effect
- Tutorial:
  - animated path guide from attacker to the center core


12) UI / OVERLAYS
- HUD:
  - timer bar
  - combo
  - score
- Overlays:
  - Main menu
  - Shop
  - Options
  - Game over


13) FILE MAP (ACTIVE)
